## Выбор и настройка мониторинга в системе

### Мотивация

#### Что даст компании мониторинг:
* **Снижение потери выручки и контрактов**. Сейчас контракты теряются из-за нарушения сроков. Без мониторинга компания не видит, где образуется задержка и не может быстро устранить причину.

* **Сокращение время реакции на инциденты**. Сейчас сигнал о проблеме - жалобы клиентов и операторов, это поздно. Мониторинг + алёрты дают ранние сигналы о проблемах
Это сокращает время обнаружения и исправления проблем и снижает нагрузку на поддержку

* **Повышение быстродействия системы**. С помощью инструментов наблюдения можно выявлять узкие места. Это помогает оптимизировать производительность

* **Управление сроками (SLA) и масштабирование**.
Бизнес осваивает новые рынки: нагрузка растёт и будет расти. 
А масштабирование без мониторинга не эффективно, поскольку будет выполняться наугад, а не по конкретным показателям

* **Поддержание роста B2B API без деградации B2C**. Нужны квоты, приоритеты, понимание нагрузки от конкретных партнёров. 
Мониторинг по B2B (RPS, ошибки, latency, объём заказов) позволит ограничивать нарушителей SLA и договариваться с партнёрами фактами

### Выбор подхода к мониторингу
* Shop API / CRM API / MES API \
Четыре золотых сигнала - единый стандарт для сервисов, позволяет быстро локализовать проблему.
RED (SLA/качество запросов) - качество сервиса глазами клиента/партнёра/оператора (скорость и ошибки)
* Сервис расчета стоимости / RabbitMQ / PostgreSQL\
USE (ресурсы CPU/память/очередь задач) - покажет, где уперлись в ресурсы (очереди, CPU, БД), то есть причину деградации.
* MES/CRM/Shop UI\
RED (время загрузки, ошибки запросов) + бизнес-метрики пути пользователя

### Метрики
**Shop API / CRM API / MES API**
* Number of requests (RPS) for internet shop API / CRM API / MES API\
Зачем: понимать нагрузку и всплески\
Ярлыки: env, service, method, status(2xx/5xx).

* Response time (latency) for shop API / CRM API / MES API\
Зачем: главный индикатор деградации (особенно первая страница MES).\
Ярлыки: env, service, method, route, status.

* Number of HTTP 500 for shop API / CRM API / MES API\
Зачем: раннее обнаружение сбоев и регрессий после релиза.\
Ярлыки: env, service, route, method.

* Number of simultanious sessions for shop API / CRM API / MES API\
Зачем: понимать одновременную активность, полезно для проблем операторов в MES.\
Ярлыки: env, service.

**RabbitMQ**
* Number of message in flight in RabbitMQ\
Зачем: показывает, что обработчики взяли сообщения\
Ярлыки: env, queue.

* Number of dead-letter-exchange letters in RabbitMQ\
Зачем: прямой сигнал, что сообщения не обработались\
Ярлыки: env, queue.

**Базы данных**
* Number of connections for shop db instance / MES db instance\
Зачем: частая причина таймаутов - кончается пул соединений.\
Ярлыки: env, db.

* Memory Utilisation for shop db instance / MES db instance\
Зачем: деградации БД из-за нехватки памяти/кэша.\
Ярлыки: env, db.

* Size of shop db instance / Size of MES db instance\
Зачем: рост данных ухудшает производительность, нужно для планирования масштабирования.\
Ярлыки: env, db.

### План действий
1. Развернуть и настроить инстанс Prometeus для хранения метрик
2. Настроить сбор метрик стороне приложений
3. Настроить экспорт метрик RabbitMQ
4. Настроить сбор метрик по Shop DB и MES DB
5. Развернуть инстанс Grafana для визуализации и дашбордов
6. Настроить дешборды в Grafana для просмотра и анализа показателей метрик
7. Настроить алерты по нарушению SLA
8. Провести тестовую нагрузку/симуляцию
